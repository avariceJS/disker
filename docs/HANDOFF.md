## Product state

Disker is a native SwiftUI macOS storage utility with native `⌘O` folder-scan and `⌘⇧O` app-bundle selection commands. It reports system volume capacity separately from selected-folder logical bytes and allocated-byte estimates. Folder scans accept up to 50 selected roots and traverse metadata-only, descriptor-relative, without following symlinks; hard links are counted once per selected root. Only regular files enter file totals; excluded special filesystem entries are separately disclosed and make their containing coverage partial. Directory and regular-file metadata are revalidated during scans; detected changes, access errors, cancellation, or excluded symlinks make coverage partial. The scan remains a non-atomic observation. Same-path growth uses only complete observations. History is local and bounded.

The app measures explicitly selected `.app` bundles. During that explicit selection, Security reads signed executable/resources locally while the selected security-scoped URL is active, and stores the declared `CFBundleIdentifier`, embedded App Groups claims, strict static-signature validation result, and signed bundle identifier with the observation. The Applications view displays declared and signed IDs with the validation status. A matching signed ID gets a stronger path match; a signature-covered App Groups claim gets a more specific shared label, without asserting developer trust or OS-granted access. Unsigned or invalid signatures retain only declared-claim evidence. Validation checks local code integrity, not Gatekeeper/notarization trust or publisher identity; no selected contents are uploaded. Shared use, current access, and exclusive ownership remain unverified. Other links remain user-selected and unverified. Sizes are never summed into an app total. The Overview shows the three largest selected roots and highlights up to three positive allocated-byte changes from the latest complete scans of the same selected paths and subfolder paths, shows both timestamps, and offers Finder reveal; a newer partial scan suppresses that path's older growth signal. Subfolder signals require the same relative path in both complete retained summaries, so omitted paths are never treated as zero. The Folders page contains per-root charts, filename categories, Git metadata, and descendant details, with a separate bounded list of nested folders containing a direct `.git` marker even when smaller than the ordinary leaderboard. These repository-marker paths compare growth only for the same relative path under the same selected root and complete observations. They are candidates, not verified project ownership. Folder cards show up to five of 30 retained filename-extension aggregates plus positive category-level changes from the prior complete scan of that exact path; partial, legacy, or truncated data suppresses those comparisons. Extensions come from names only and do not establish content or purpose. Associated folders show change only against the previous complete measurement of that exact path. Exact-name development-storage hints are descriptive, not safety or ownership claims. Duplicate review is a separate content-reading action after confirmation; after the final metadata pass, changed or unavailable candidates are excluded and groups with fewer than two valid files are hidden. Its dry-run plan retains the source verification time, warns that files may have changed since, requires an exact keeper, offers Finder reveal for the candidate and kept copy, and reports risk/reclaimable bytes as unknown. There is no deletion action.

The manual RAM view also stores optional macOS `vm.swapusage` totals, available and used bytes. A successful zero-allocation sample is shown as “No swap allocated,” separately from a sysctl failure. History plots swap use when present. RAM sampling can be opted into every five minutes while Disker is active; it pauses while the app is inactive, suppresses overlapping samples, and resets off on next launch. It installs no background service. This does not measure system memory pressure or prove a process leak.

The Folders page now retains up to 20 read-only security-scoped bookmarks for explicitly selected folders and application bundles. Saved scopes are local, bounded, individually removable, refreshed when a stale bookmark resolves, and usable only through a manual rescan; Disker does not access them on launch or monitor them. Clearing local history also removes these bookmarks. The bookmark file is written with owner-only permissions. App-folder association paths remain separate metadata.

## Safety and platform limits

Only `/Users/root1/Desktop/disker` is in scope. Never modify Brain, SRO Robot, Kingston, or real user files. Do not add deletion or claim that names, duplicate contents, age, or app associations prove data is disposable/owned. Keep the sole development branch `main`; never rewrite or force-push history.

The current Disker build is unsigned and unsandboxed, and is not App Store-ready. A signed sandboxed build still needs to validate selected-folder traversal, bookmark persistence/resolution and stale refresh, duplicate reads, local history access, and protected-folder failure states. Disker locally validates selected static code signatures, but does not verify Gatekeeper/notarization trust or publisher identity. App and group path labels do not prove current access or exclusive ownership; matching App Group data is explicitly shared. Representative interactive and scan-load resource measurements are also open. Latest visual inspection of current screens remains blocked by unavailable CUA window access; do not spend significant time on optional tooling.

The mission remains in progress: Disker does not automatically discover app support data, run background monitors/notifications, report system-wide memory pressure, or provide general cleanup plans. Swap accounting is an optional on-demand metric; no swap was allocated during this session. RAM sampling remains on-demand unless the user enables the five-minute active-app toggle. The only cleanup preview is a read-only duplicate dry run. No file removal is implemented.
