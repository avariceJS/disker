## Current product

Disker is a native SwiftUI macOS app with Overview, Applications, Folders, Duplicates, History, RAM, and About. It separates macOS-reported volume capacity from selected-path logical bytes and allocated-byte estimates, shows coverage/freshness, and retains bounded local observations. Complete same-path comparisons drive folder, directory, extension, large-file, candidate, and capacity trends. Overview retains the largest unrecovered available-space drop of at least 100 MiB in bounded history and calls out when no selected-folder scan explains it; capacity is never attributed to folders without aligned complete same-path evidence. After a scan, Overview reports complete selected roots over selected roots and the latest scan time; incomplete roots remain explicitly unknown, and this is not whole-volume coverage. When the latest selected-root scans are partial, the capacity callout shows their measured-size estimates, exclusions, and a clear warning that current size is not growth. Application footprint review uses explicit selection and evidence-scoped associations. Duplicate verification reads selected candidate contents only after separate in-app consent and produces a dry-run after the user picks a keeper. No deletion action exists.

Developer-artifact review shows measured paths, name/Git-marker evidence, risks and consequences, logical and allocated estimates, coverage, overlaps, and complete-history deltas. It now includes up to three read-only investigation prompts: positive complete same-path growth first, then a complete candidate at least 100 MiB allocated. Formatted sizes, confidence, coverage, overlap, and a link to detail are provided; reclaimable space remains unknown. Partial roots suppress prompts and partial subtrees are excluded. This is not general cleanup discovery or a deletion plan. RAM uses snapshots and cautious sampled signals; leak diagnosis and a background service are not implemented.

Folders detail also includes a bounded review of files with at least 100 MiB allocated estimate and a filesystem modification timestamp at least 180 days old. It requires complete coverage and an untruncated largest-file inventory. The UI exposes exact path, logical and allocated sizes, date/age, and Finder reveal while explaining that old modification time does not mean unused and reclaimable space is unknown. The metadata review does not read contents or offer cleanup.

Full file-change tracking now runs alongside the capped dashboard summaries. A complete selected-root scan records every regular-file path in the explicit no-follow scope (hard links count once at their deterministic path), then stores a separate local baseline and the latest exact-path comparison. Dashboard history reads decode only reports and aggregate trends. Snapshot format v2 stores sorted relative paths and byte counts in a streaming LZFSE-compressed payload; recording expands only the prior manifest for the same selected root, then releases it before packing the replacement. Legacy v1 snapshots are converted one root at a time on the next successful complete record. Corrupt payloads and retention-bound violations fail closed without replacing the store. Synthetic checks confirm exact path comparisons across migration, rejection of a corrupt packed snapshot without modifying it, dashboard reads that ignore snapshot payloads, and compatibility with stores lacking optional trends. The next complete scan reports added, resized, and no-longer-present paths, net logical and allocated deltas, separate gross allocated-estimate growth and reduction totals, and up to 100 changed paths. The gross totals prevent simultaneous removals from hiding how much added or enlarged paths grew. They are estimates of allocated bytes, not physical reclaimable space. A separate local trend retains 120 aggregate complete-scan intervals per root and 2,400 total, without duplicating path lists; the Folders detail can disclose the latest eight. Detailed changed paths remain only for the latest comparable scan. Volume identity changes clear the per-root trend. Partial scans do not add a point. Older reports and stores decode with the new optional fields/history unavailable. The full inventory is bounded to 500,000 entries per root, 750,000 total, 50 roots, and a 128 MiB private binary plist. Partial, cancelled, concurrent-change, inaccessible, special-file, volume-boundary, accounting-overflow, or capped inventories do not replace a baseline. Symlink targets remain excluded and named in the UI. First scan creates a baseline only; no earlier growth can be recovered. This identifies net on-disk differences between scans, not short-lived activity or causal ownership. Explicitly opted-in roots now receive event-assisted and scheduled metadata scans while the Disker window remains open; short-lived activity, unselected roots, and periods while the window is closed are not reconstructed.

It also compares large file paths with the immediately prior complete inventory of the same selected root and volume, but only when both bounded summaries are untruncated and the current record is latest. Rows say “Not present in prior complete inventory”; they do not claim the file was created, is unused, belongs to a project, or is reclaimable. A newer partial/cancelled observation suppresses results.

The app-removal review now shows a measured selected-scope subtotal only for disjoint, explicitly selected scopes whose latest observations are complete, uncancelled, non-overflowed, nonnegative, and safely addable. Shared or multi-owner scopes are excluded. Any other missing or unsafe scope withholds the subtotal with a path-specific reason. This is a subtotal of selected measurements, not exclusive app ownership, exact SSD use, or reclaimable space. A second read-only disposition now makes each path's cleanup-review status and evidence visible; macOS-managed roots are excluded, unknown data remains inspect-only, and no row is presented as safe to delete.

If a selected app bundle path is unavailable, the owner can explicitly check the exact saved associated directory paths. A descriptor-based walk uses no-follow metadata operations for every path component, rejects ancestor and final symlinks, and rejects raw `.`/`..` before normalization. Results distinguish available directories from missing/unreachable, access-unknown, non-directory, symlink, and invalid/stale/mismatched bookmark cases. It does not enumerate descendants, read file contents, or refresh bookmarks. Association and bookmark changes invalidate in-flight checks. This supports investigation only; it does not confirm uninstallation or safe cleanup.

The bundle-path check uses the same typed statuses. An access or bookmark failure is shown as unconfirmed presence rather than as a missing app. The associated-folder prompt likewise says only that the bundle path could not be confirmed; it does not call this an uninstall finding.

Applications now also has a read-only Spotlight discovery catalog, separate from measured bundles. It queries only existing `/Applications`, `/System/Applications`, and `~/Applications` directories plus any extra folder the user explicitly selects in that page. It filters indexed bundle results to those lexical scopes, excludes nested `.app` helpers and any path with a symlink component, and retains at most 500 results. The page must be open for live query updates. Each result requires a Measure action and exact-path confirmation in the native picker before its bundle is scanned. Spotlight coverage remains incomplete when items are excluded or unindexed; discovery is metadata-only and makes no claim about installation time or usage. First-seen/last-seen path dates are stored in private local history, capped at 500, and cleared with Disker history. Synthetic tests cover filtering, deduplication, nested apps, ordering, timestamp retention, and the history bound.
