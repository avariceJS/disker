## Product

Disker is a native SwiftUI macOS app installed at `~/Applications/Disker.app`. Its screens are Overview, Applications, Folders, Duplicates, History, RAM, and About. It reports macOS volume capacity separately from selected-path file-tree estimates; folder scans disclose logical bytes, allocated-byte estimates, coverage gaps, symlinks, volume boundaries, and selected-path history. It stores bounded local history (up to 180 observations), compares complete observations for the same path and volume, and shows capacity charts, folder/directory growth, extension summaries, and up to 20 largest files. When capacity decreases, Overview can show a complete selected-root growth comparison that overlaps or is within 60 seconds of the capacity interval; this is timing context only, overlapping roots are not added, and unmeasured storage remains unassigned. A file-growth signal requires the same relative path in both complete top-file summaries; omitted rows remain unknown.

Application bundle measurement and read-only app-footprint review rely on explicit selection and evidence-scoped associations. Review rows now distinguish App Group claims or paths linked to other apps, possible caches, the selected bundle, and unknown or potentially unique data, each with recovery/use uncertainty. Associations do not prove current use. These are caution labels, not removal recommendations. Duplicate verification reads content only after the user chooses roots and confirms a candidate estimate; its review is dry-run and has no deletion action. RAM is a separate subsystem with point samples, optional active-app-only monitoring, system-pressure transitions, and cautious process-growth language. Automatic monitoring is off after relaunch. Disker does not offer file cleanup/deletion.

Overview and selected-folder details now open a read-only developer-artifact review from the latest selected scan. It shows exact paths, observation time, separate logical and allocated estimates, classifications, consequences, evidence, coverage, truncation, and overlapping paths. Unsafe relative paths from stored summaries are rejected. Finder reveal and native re-selection are available; reclaimable bytes remain unknown and there is no deletion action.

The saved scan-root list shows each path's latest retained measurement, time, logical bytes, allocated estimate, and coverage. It shows a delta only for complete same-path/same-volume observations; a newer partial scan suppresses stale growth. For complete folder and subfolder growth observations at least five minutes apart, the overview also shows the straight-line observed byte pace scaled to 24 hours; this is descriptive, not a forecast. A new in-memory opt-in supports metadata-only scans for individually selected saved roots while Disker is active, at selectable 5/15/30/60-minute intervals (15-minute default). It serializes work behind scans, duplicate verification, and own-footprint measurement; inactive app state cancels scheduled work. User cancellation or bookmark failure pauses that root. Opt-ins reset off and cadence resets to 15 minutes after relaunch; no root is accessed at launch.
