## Current product

Disker is a native SwiftUI macOS app with Overview, Applications, Folders, Duplicates, History, RAM, and About. It separates macOS-reported volume capacity from selected-path logical bytes and allocated-byte estimates, shows coverage/freshness, and retains bounded local observations. Complete same-path comparisons drive folder, directory, extension, large-file, candidate, and capacity trends. Overview retains the largest unrecovered available-space drop of at least 100 MiB in bounded history and calls out when no selected-folder scan explains it; capacity is never attributed to folders without aligned complete same-path evidence. After a scan, Overview reports complete selected roots over selected roots and the latest scan time; incomplete roots remain explicitly unknown, and this is not whole-volume coverage. When the latest selected-root scans are partial, the capacity callout shows their measured-size estimates, exclusions, and a clear warning that current size is not growth. Application footprint review uses explicit selection and evidence-scoped associations. Duplicate verification reads selected candidate contents only after separate in-app consent and produces a dry-run after the user picks a keeper. No deletion action exists.

The Duplicates page also surfaces same-logical-size file candidates from complete regular-file inventories of explicitly selected roots. This metadata-only index uses a 1 MiB threshold; logical size and allocated-byte estimates remain separate. It does not read file contents or label size matches as confirmed duplicates. The existing verification flow still requires fresh folder selection and explicit consent before reading contents. Index limits are 20,000 size buckets, 40 displayed groups, and five paths per group; omitted coverage is disclosed, and older summaries are hidden after a newer folder observation. A selected folder may have partial overall coverage because excluded links or other items remain outside the complete no-follow regular-file inventory.

Selected project roots with a direct `.git` marker can link exact external folders through an explicit picker. Nested Git-marked candidates now offer a separate metadata-only measurement after the user confirms the exact candidate path in `NSOpenPanel`; this stores an independent root observation instead of folding it into the parent total. Project rows keep measurements separate, disclose partial coverage, overlaps, and multi-project links, and never assert ownership or sum a project total. If a selected app bundle path is unavailable, the owner can explicitly check the exact saved associated directory paths.
